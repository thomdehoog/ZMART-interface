# Review of the ZMART interface, 10 October 2026

This is a code review of the ZMART interface as it stood on `main` at commit
`b5aea0a` (version `0.1.0rc1`, "the framework knows no workflow, and a workflow
installs from another repository"). It was written by Claude at Thom's request.
ZMART-viewer was reviewed on the same day; its report is
`docs/REVIEW_2026-10-10.md` in that repository, and the section
"Where the interface meets the viewer" below covers what the two share.

**How to read it.** Every finding gives the file and line, what is wrong, a
situation in which it goes wrong, and a fix. Paths are relative to
`zmart_interface/` unless they start with `docs/` or name a top-level file.
*Confirmed* means the code path was traced or the fault was reproduced;
*plausible* means it is believed but was not fully traced or run.

**What the review did and did not do.** The code was read and the tests were
run on Linux, in a copy of the repository. Nothing was tested on Windows or on
a real microscope. The list at the end names the files that were only searched
and not read; no conclusion should be drawn about those.

## Verdict

The interface is close to a release, but four things should be fixed first:

1. Any web page open on the same computer can send commands to the bridge.
2. A name supplied by the page reaches a folder deletion without being checked.
3. Connecting again leaves the old scan still moving the stage.
4. Made-up demonstration focus heights can reach a real stage through a
   protocol file.

## Must fix before release

### 1. Any web page open on the computer can drive the microscope (confirmed, reproduced)

- **Where:** `framework/bridge/server.py:303`, `:433`, `:441-446` (the header
  `Access-Control-Allow-Origin: *` on every answer and on the preflight),
  `:437-439` (the body is parsed whatever its `Content-Type`), `:457-475` (no
  check of `Host`, `Origin` or a token anywhere).
- **What is wrong:** the bridge listens on 127.0.0.1 only, which is good, but
  it trusts every request that reaches it.
- **How it goes wrong:** `POST /api/connect` and then
  `POST /api/xyz {"x":1234,"y":2345}` were sent with
  `Origin: https://evil.example`, a foreign `Host` and
  `Content-Type: text/plain` (so that a browser sends no preflight). Both were
  answered with 200 and the mock stage moved. The standalone bridge described
  in `docs/install-on-a-microscope.md` uses the fixed port 8600. The launcher
  uses a random port, which only slows an attacker down.
- **Fix:** refuse a request whose `Host` is not `127.0.0.1:<port>` or
  `localhost:<port>`, and whose `Origin`, when present, is not the bridge's own
  or the `--dev` address. Send `Access-Control-Allow-Origin: *` only with
  `--dev`. Better still, let the launcher make a token for each run and require
  it on every `/api/` call.

### 2. `acquisition_type` from the page reaches `rmtree` unchecked (confirmed, reproduced)

- **Where:** `framework/bridge/scan.py:140-145` calls
  `pictures.replace_the_acquisition` (`framework/bridge/pictures.py:166-197`)
  before the name check in `prepare_acquisition` has run.
- **What is wrong:** `run / "positions" / acquisition_type` and
  `run / acquisition_type / "view"` are built from text the page supplies. An
  absolute path replaces the run folder altogether.
- **How it goes wrong:** with a session open,
  `POST /api/scan {"acquisition_type": "<any absolute folder>", "positions": []}`
  was answered with 200. It deleted that folder's `view/` and every
  `*.ome.zarr` folder directly inside it. Together with finding 1, any web page
  can delete image data anywhere the user can write.
- **Fix:** call `output._validate_name(acquisition_type)` as the first line of
  `start_scan`, and again in `replace_the_acquisition` and `view_of`. Do the
  same for `kind` in `server.py:388-420`: `/view/<kind>/…` is not checked
  either, and on Windows a backslash in `kind` leaves the run folder.

### 3. Connecting again leaves the old scan moving the stage (confirmed, reproduced)

- **Where:** `framework/bridge/connecting.py:64-140` (no check for an open
  session or a running scan; the scan's record is reset at `:120-123`),
  `framework/bridge/scan.py:48-66` (the scan asks for `state.session` afresh
  for every field), `scan.py:133-134` (the "already running" check reads the
  record that connecting has just reset).
- **How it goes wrong:** a scan of 24 fields was started on the mock, and
  `/api/connect` was sent again at field 9, as a reloaded page would. The
  record then said `running: False`. The old scan went on moving the stage (x
  went from 11000 to 24000 µm in the next three seconds) and wrote its images
  into the new run folder. A second `/api/scan` was accepted, so two scans took
  turns moving the stage. The first controller session was never closed.
- **Fix:** in `connect`, refuse while `a_run_has_the_stage()`. Otherwise ask
  the scan to stop, wait for it, and disconnect the old session first. Give
  each scan the session and the run it started with, and let it stop when
  `state.session` is no longer that session. Put a lock around `start_scan`.

### 4. Demonstration focus heights can reach a real stage through a protocol file (confirmed by reading, not run)

- **Where:**
  - `workflows/target_acquisition/steps/focus_strategy/focus-map.js:67-80`:
    the "parked" strategies and `PREVIOUS_SURFACES` (invented planes around
    −412 µm).
  - `workflows/target_acquisition/shared/run-document.js:49-50`: the defaults
    `zFixed: -412` and `reuse: "run_0714_a"`.
  - `workflows/target_acquisition/shared/protocol.js:117-125`: `applyProtocol`
    copies `strategy` and `zFixed` from the file without checking them.
  - `workflows/target_acquisition/steps/focus_strategy/run.js:16`: a strategy
    other than `plane` finishes at once.
  - `steps/scan_the_overview/run.js:33-35` and `steps/acquire_targets/run.js:42`:
    both drive to `surfaceZAt`.
- **How it goes wrong:** a `protocol.json` with `"focus": {"strategy": "fixed"}`
  is opened. The focus step finishes without measuring anything. The overview
  scan then drives every field to the absolute height `zFixed`, and every
  protocol the page saves carries −412 there. With `"reuse"` it drives to an
  invented tilted plane. Such a file can come from editing by hand, from an
  older page, or through `POST /api/protocol/save` (finding 1). The driver's
  travel limit is then the only protection.
- **Fix:** remove the demonstration numbers. In `applyProtocol` and in
  `focusSurface`, refuse every strategy other than `plane` until the others
  are really built.

## Should fix

### 5. The z offset is applied twice when a target's focus stack shows no peak (confirmed, reproduced)

- **Where:** `parts/microscope/live.js:465` adds the offset to the map height;
  `:478` reads `standing`, which already includes it; `:492` adds it again.
- **How it goes wrong:** map height 100 µm, offset 5 µm, a stack with no peak.
  The stage was sent to z = 105 and then to z = 110. The comment at `:446-447`
  promises the map's height.
- **Fix:** in the no-peak branch use `at = { x, y, z: standing }` when `zMap`
  was a number. `live-acquire.test.js` has no case with an offset other than
  zero; add one.

### 6. The microscope's refusal is lost on two paths that move the stage (confirmed by reading)

- **Where:** `live.js:322-324` (a lost focus point: the reason goes to
  `console.warn` and the point carries none) and
  `workflows/target_acquisition/the-canvas.js:158-170` (a refused double-click
  drive returns `null` after a `console.warn`).
- **How it goes wrong:** the driver declines a move as outside the travel. The
  operator sees a "lost" focus point that looks like a failed autofocus, or a
  double-click that does nothing. The README promises that "the interface shows
  that sentence where you pressed", and the window has no visible console.
- **Fix:** keep `why.message` on the lost point and show it in its row. Send
  the refused drive to `status.say`.

### 7. Carrier alignment corrects a shift only, never a rotation (confirmed by reading)

- **Where:** `workflows/target_acquisition/shared/stage.js:177-197` (the mean
  offset of the anchors) and `:545-553` (`toStage` only adds that offset).
- **What is wrong:** `steps/define_carrier/carrier-panel.js:240-242` places
  four anchors so that "the rotation is read off the distance between them",
  but no rotation is ever calculated.
- **How it goes wrong:** a plate seated half a degree off puts the far wells
  about 1 mm from where the stage is sent, with no warning. Two anchors that
  disagree by millimetres (the wrong well, or a mirrored axis) are averaged
  without a word.
- **Fix:** fit a shift and a rotation when two or more anchors are set, and
  show how well they agree. At the least, warn when the anchors disagree by
  more than a tolerance.

### 8. A guessed pixel size or frame size looks the same as a measured one (confirmed by reading)

- **Where:** `framework/bridge/readings.py:27` and `:141-143` (`pixel_um`
  falls back to 1.0 and the frame to 512 pixels),
  `framework/bridge/discovery.py:29`.
- **How it goes wrong:** the comment at `readings.py:139-140` says a driver
  can report `pixel_size` as `None` when the job's geometry cannot be read.
  The page then plans the scan with 512 µm frames, which leaves gaps or
  overlaps, and detection converts diameters at 1 µm per pixel. Nothing says
  that the value is a guess.
- **Fix:** answer with `"guessed": true`, show it in the summary, and do not
  let the scan-area step continue on a guess. Raise an error in `find_targets`.

### 9. `drive_to` uses 0.0 for an axis the driver did not report (confirmed by reading; plausible as a hazard)

- **Where:** `framework/bridge/stage.py:83-88`.
- **How it goes wrong:** a driver whose `get_xyz` has no `z.position` receives
  `set_xyz(x, y, 0.0)` on a plain double-click in x and y, which is an absolute
  move to z = 0. The scan already avoids exactly this (`scan.py:56-65`).
- **Fix:** raise an error when an axis that should stay where it is has no
  reading.

### 10. `connect` can leave a half-open session (confirmed by reading)

- **Where:** `framework/bridge/connecting.py:109` and what follows.
- **How it goes wrong:** `info["output_root"]` is missing, or
  `prepare_experiment` fails (for example, no permission to write). The error
  leaves `state.session` open while `state.run` is `None` or still points at
  the previous run. The operator reads only `'output_root'`.
- **Fix:** put the rest of `connect` inside the existing `try`, so that it
  disconnects on failure, and give the error a full sentence.

### 11. The mock microscope needs the internet for its first image (confirmed, reproduced)

- **Where:** `mock_microscope/driver.py:676-683` (`skimage.data.kidney()`
  downloads the sample from gitlab.com).
- **How it goes wrong:** where gitlab.com cannot be reached, every capture
  fails with "the microscope could not capture an image: ProxyError …".
  `server.py:8-9` says "the microscope computer has no network", so the mock
  that is always offered cannot take an image there. This one cause produced
  all 35 failures in the Python tests (see "The tests").
- **Fix:** ship one small plane with the package, or fall back to a drawn
  specimen with a sentence that says so.

### 12. `register_workflow` can delete a package, and installing is not all-or-nothing (confirmed, reproduced)

- **Where:** `framework/workflow_library.py:139-144`.
- **How it goes wrong:** `register_workflow(<library>/<folder>)`, a natural way
  to "repair" an installed workflow, deletes the target and then fails with
  `FileNotFoundError`; the package is gone. A copy that fails halfway also
  leaves the old version deleted.
- **Fix:** refuse when the source and the target are the same folder. Copy
  into a temporary folder beside the target and swap it in at the end.

### 13. A broken package does not appear on the page at all (confirmed)

- **Where:** `workflow_library.py:112-114` lists a package whose manifest
  cannot be read without a `bundle`; `framework/window/installed-workflows.js:130`
  skips entries without one before `refuse` is called.
- **How it goes wrong:** a package with invalid JSON in `workflow.json` never
  appears in the chooser, not even greyed out. The docstring at
  `workflow_library.py:99-101` promises the opposite.
- **Fix:** call `refuse(folder, name, listed.error)` when `listed.error` is
  set, before the bundle check.

### 14. A workflow's Python half can replace the bridge's own routes, and a package installed while the bridge runs has none (first confirmed and reproduced, second confirmed by reading)

- **Where:** `framework/bridge/workflows.py:50-51` with `server.py:62-69`;
  `workflows.py:64-78`.
- **How it goes wrong:**
  - A package in a folder named `targets` that registers `discover` replaced
    the built-in `POST /api/targets/discover`. Folders named `focus`, `scan`,
    `protocols` and `xyz` collide in the same way.
  - Python halves are loaded only at start-up, yet `listing()` shows a newly
    installed package without an error. Its steps then answer 404 in the
    operator's hands.
- **Fix:** refuse a route that already exists and reserve the built-in first
  segments. Mark a package whose half was not loaded with "restart the
  interface to finish installing this workflow".

### 15. Nothing is released when the window closes (confirmed by reading)

- **Where:** `launcher.py:96-98` (no disconnect, `warm.close()`,
  `viewer_service.stop()` or server shutdown after `webview.start()` returns);
  `parts/storage/viewer_service.py:205-209` (`shutdown()` without
  `server_close()`); `mock_microscope/__init__.py:94-97` (the started process
  is never kept or collected).
- **How it goes wrong:** closing the window during a session leaves the
  controller session open, and the analysis workers and the mock's window are
  left running. Every connect and disconnect leaves one listening socket open.
- **Fix:** wrap `webview.start()` in `try/finally` and call
  `connecting.disconnect()` there; add `server_close()`.

### 16. The focus Interrupt cannot reach a score that hangs (plausible)

- **Where:** `parts/analysis/warm.py:71` and `:101-110` (no time limit, by
  design); `live.js:338-341` (the stop only sets a flag that is read between
  points); `framework/bridge/focus.py:41`.
- **How it goes wrong:** an analysis worker that has stopped answering blocks
  the `/api/focus/score` request for ever. `state.focus["running"]` stays
  true, so scans and new maps are refused until the operator reconnects.
  Stopping detection calls `warm.close()`; stopping focus does not.
- **Fix:** give the bridge a `/api/focus/stop` that calls `warm.close()`.
- **Related, also plausible:** `Analysis.run` returns the first result in the
  queue without a job key (`warm.py:103-104`), so two overlapping calls can
  receive each other's answers. `run_each` already gives its jobs keys.

### 17. Dependencies follow default branches while the code expects exact behaviour (confirmed by reading)

- **Where:** `pyproject.toml:26-32` and `:57` (`zmart-controller`,
  `zmart-viewer`, `zmart-analysis` and `zmart-drivers` are all installed from
  `git+https://…` with no tag or commit); `viewer_service.py:62`
  (`>=0.5.0rc1,<0.6`); `neuroglancer-workers.mjs:177-190` (the committed page
  contains the viewer's patch file from the time it was built).
- **How it goes wrong:** on the day ZMART-viewer's `main` becomes 0.6, a fresh
  install connects without a picture (one sentence on `/api/viewer`, nothing
  more), and `test_building_twice_gives_the_committed_page` fails although
  nothing changed in this repository. Two microscope computers installed a
  week apart run different controllers.
- **Fix:** pin each to a tag or a commit (for example `@v0.5.0rc1`) and raise
  them deliberately, together with the built page.

### 18. "The framework knows no workflow" holds for the page, not for the bridge (confirmed by reading)

- **Where:** `framework/knows-no-workflow.test.js:21` checks imports only, and
  only in `window/` and `rules/`. Under `framework/bridge/`:
  - `connecting.py:61`: `EXPERIMENT = "target-acquisition"`; every workflow's
    run folder gets that name, and `protocols.py` searches for it.
  - `connecting.py:20`, `:84`: imports `mock_microscope` and treats it
    specially.
  - `discovery.py:41`: `state.records["overview"]`.
  - `targets.py`, `scan.py`, `focus.py` and about thirty routes in
    `server.py:91-285` belong to target acquisition.
- **What is wrong:** `docs/architecture.md:74-76` says "nothing under it names
  a step, a workflow or an instrument, and a unit test keeps it so".
- **Fix:** either move these modules under `workflows/target_acquisition/` as
  that workflow's own Python half, which is the mechanism this release adds,
  or narrow the sentence and the test's description to the JavaScript
  framework.
- **On the page side** no stale imports or fixed step names were found in
  `framework/window/*.js` or `framework/rules/*.js` (`main.js`,
  `installed-workflows.js`, `runtime.js` and `versions.js` were read in full;
  the rest was searched).

## Nice to have

19. **Raw Python errors reach the operator** (all three reproduced).
    `server.py:118`: `/api/setting?type=a=b` answers "dictionary update

21. **A plane with an unknown `x_um` is placed at the stage origin**
    (`parts/storage/zarr_positions.py:465-466`, `or 0.0`), while
    `pictures.py:162-163` raises an error for the same input. Refuse it in
    both places.
22. **The focus shift cannot tell a relative sweep from an absolute stack that
    starts at the stage height** (`parts/microscope/focus_run.py:76-95`,
    plausible). Such a driver would shift every focus height by half the stack
    range. Let the driver say which it is.
23. **The backend contract test moves a real stage without asking when it is
    pointed at a bridge** (`parts/microscope/backend-contract.js:44-52`,
    `:129`: a sixth of the travel, then a fixed 5000 µm, at whatever height
    the objective stands). Require an explicit yes.
24. **The viewer's server is open to every origin while `allow_open=True`**
    (`viewer_service.py:115`, `:655-687`, plausible). Any web page that finds
    the port can ask the viewer to open any folder. The comment at `:21-23`
    ("opens nothing to anybody who could not already read the disk") does not
    hold for a browser. Allow only the bridge's own origin.
25. **Package data is not collected from subfolders** (`pyproject.toml:71`,
    `"window/build/*"`). This is fine today with three files; a build that
    makes a subfolder would lose it from the wheel without a message.
26. **The README's environment variable line does nothing in PowerShell**
    (`set ZMART_ANALYSIS_WORKFLOWS=C:\…` in a `bash` block). It is `cmd.exe`
    syntax and lasts for one session. `docs/install-on-a-microscope.md` uses
    `setx`, which is right.
27. **Gaps in the automatic checks** (`.github/workflows/tests.yml`): ruff is
    configured but never run, and the browser tests run only by hand, so the
    only tests that go through the real page never stop a merge.

## Where the interface meets the viewer

These are the points where the two repositories depend on each other. The
first four are worth acting on.

- **The interface widens what the viewer exposes.** `_allow_the_page_to_read`
  (`viewer_service.py:655-687`) replaces `end_headers` and `do_OPTIONS` on the
  viewer's handler class, so that every answer carries
  `Access-Control-Allow-Origin: *`. The viewer itself checks no `Host` or
  `Origin` (its review, finding M3). One argument on `make_server`, for
  example `allowed_origins=`, would remove this patching and close both.
- **Nothing pins the viewer** (finding 17).
- **The neuroglancer patches are kept the same by hand in two places:**
  `patches/neuroglancer+2.41.2.patch` here and
  `gui/source/scripts/patch_neuroglancer.mjs` in the viewer, whose comment
  still points at the old place in ZMART-microscopy. Both pin neuroglancer
  2.41.2.
- **`span` appears to be ignored.** `parts/canvas/viewer-panel.js:203-217`
  sends `span` to the viewer's `/api/measure`; nothing was found in the
  viewer's server that reads it.

**What no test covers on the paths that move the stage**

- A request with a foreign `Origin` or `Host`, or a hostile `acquisition_type`
  or `kind`.
- Connecting again, disconnecting, or starting a second scan while one runs.
- `acquireTargets` with an offset other than zero.
- `applyProtocol` with a strategy other than `plane`.
- `drive_to` with a missing axis, or a declined `set_xyz` reaching the operator.
- Anchors that disagree, or a rotated carrier.
- `register_workflow` with the source equal to the target, a failed copy, or a
  route that already exists.

## What is good

- `Instrument.unwrap` (`parts/microscope/instrument.py`) is the one place that
  turns `success: False` into a sentence, refuses answers that are not in the
  agreed shape, and never repeats a move.
- The scan refuses to invent a height (`scan.py:56-65`), and the comments
  record why each rule exists. They read like a record of past incidents and
  are valuable.
- `move_record_images` checks every source and destination before the first
  move and undoes its work on failure.

  followed by a start safe from old worker threads, and publishing never holds
  up acquisition.

  and one failed package not blocking the others. Its two Playwright tests
  build, install and walk through a real package.

  (`workflow_library.package_file`, `_send_the_page`) cannot be led outside
  their folders as written.
- The stage watch's time limit, and the bridge's `get_xyz` that does not wait
  during a run.
